# 飞书多维表任务表使用说明

这张任务表用于告诉 CompetitiveTracking **要监控哪些商品、从哪个平台采集、是否发送消息以及发送给谁**。程序每次运行都会先读取任务表，再按平台筛选商品；商品数据结果会写入对应的结果多维表、历史二维表，并根据推送设置发送飞书消息。

任务表入口：[商品监控-控制台](https://qcn9sleukmer.feishu.cn/base/Jpd2bH2CtarZ3UsR0OBcBSxjnng?table=tblIGBjHB1XgNbHv&view=vewvhu2V6C)。

截图中的任务表按“平台”分组。分组只是为了查看方便，程序实际按“平台 + 商品ID”识别商品。不同平台即使出现相同的数字，也不会被当成同一个商品。

### **字段说明**
| 字段 | 填写方式 | 程序用途 |
| --- | --- | --- |
| **商品ID** | 填平台商品的唯一 ID，建议粘贴为文本 | 与“平台”一起定位商品；不能为空 |
| **自定义-商品名** | 填运营便于识别的名称，例如“雨伞主推款” | 显示在消息卡商品匹配 |
| **平台** | 使用 `mercado`、`shopee` 或 `tiktok` | 决定使用哪个平台采集器打其他名称 |
| **监控开关** | 选择“开启” 后才会监控商品 | 只有“开启”的任务才会进入商品采集 |
| **推送开关** | 选择“开启” 后每天推送该商品数据 | 控制该任务是否发送飞采集和表格写入 |
| **是否竞品** | 仅用于后续运营筛选，非必填项 | 写入结果表的“竞品”字段，并用于后续运营筛选 |
| **数据推送人** | 接受推送消息的人员 | 必须有人员，任务才会这里的人 |
| **记录-多维表链接** | 不填，每日数据结果 | 方便运营从任务行打开最新结果 |
| **记录-二维表链接** | 不填，每日历史记录结果 | 方便查看历次采集；程序按采 |
| **负责人** | 选填 | 用于结果表归属和后续不是负责人 |
| **备注** | 自由填写 | 仅供人工备注，当前不会参与商品匹配 |
```text
PS：满足下面条件，才会被读取为采集目标
1. **平台**是 `mercado`、`shopee` 或 `tiktok`。 2. **商品ID**不为空。 
3. **监控开关**为“开启”。 4. **数据推送人**不为空。
```
### **商品ID的获取**
举例如下：
tiktok商品链接：https://shop.tiktok.com/view/product/1737194607628027090?region=BR&local=en ，
则tiktok商品ID为：1737194607628027090
虾皮商品链接：https://shopee.com.br/product/955204066/22329034432，则商品ID：22329034432
美客多商品链接：https://www.mercadolivre.com.br/lancheira-marmita-bolsos-laterais/up/MLBU4813895273，
则mercado商品ID：MLBU4813895273

因此应填写：
https://shop.tiktok.com/view/product/1737194607628027090?region=BR&local=en    商品ID 为：1737194607628027090 。https://shopee.com.br/product/955204066/22329034432 商品ID 为：
```text
商品ID：1737194607628027090
平台：tiktok
```

`?region=BR&local=en` 是 URL 查询参数，不属于商品 ID。TikTok ID 通常是 19 位数字，必须完整保留，不能转成带小数点的数字，也不能删掉前导字符。FastMoss 查询链接中的 `words=1737194607628027090` 使用的是同一个 ID。

### Mercado（美客多）示例

商品 ID 通常带有 `MLB`、`MLM`、`MLA`、`MLBU` 等站点或商品类型前缀，例如：

```text
商品ID：MLB6984707226
平台：mercado
```

如果商品链接中出现类似 `/p/MLB6984707226`，取 `/p/` 后的 `MLB6984707226`；如果系统返回 `MLBU4813895273`，也要完整保留 `MLBU` 前缀。保留完整的字母前缀和数字，并建议统一使用大写。不要填写卖家 SKU、跟卖商品 ID 或店铺 ID。

### Shopee 示例

Shopee 商品 ID 通常是纯数字，例如：

```text
商品ID：24293145097
平台：shopee
```

如果链接或页面同时出现店铺 ID 和商品 ID，应填写页面标注的 **Product ID / 商品ID / Item ID**，不要把店铺 ID 与商品 ID 拼接。纯数字 ID 也要按文本保存，避免表格自动变成科学计数法或丢失位数。

## 三、按截图新增一条任务

以 TikTok 商品为例：

| 商品ID | 自定义-商品名 | 平台 | 监控开关 | 推送开关 | 是否竞品 | 数据推送人 |
| --- | --- | --- | --- | --- | --- | --- |
| `1737194607628027090` | 雨伞主推款 | `tiktok` | 开启 | 开启 | 否 | 选择胡钦腾 |

然后按需要填写负责人，并把“记录-多维表链接”和“记录-二维表链接”填成 TikTok 对应结果表链接。保存后，下一次 `once` 或 `serve` 运行会读取该任务。

如果暂时只想采集、不想给运营发消息，可以保留“监控开关=开启”，把“推送开关”设为“暂停”。如果连采集也要停止，把“监控开关”关闭。

每次执行 `once` 或 `serve` 时，程序按平台调用原有清洗逻辑后，会在终端打印一行 `清洗后的任务数据`。其中 `targets` 就是实际提交给平台采集器的数据；被过滤掉的空商品 ID 不会出现在 `targets` 中，同一个商品如果有多个推送人，会保留在同一个目标的 `records` 中。

## 四、结果和消息如何对应

- **多维表结果**：每个平台独立一张表，按“商品ID”更新已有记录；同一个商品不会因为每天采集而重复创建行。
- **二维表历史**：每次成功采集都追加一行，保留当时的采集时间和指标；不会覆盖以前的历史值。
- **飞书消息**：按“数据推送人”逐人发送。卡片首行显示 `平台 · 商品ID - 自定义-商品名`，随后显示平台标题、价格、销量等指标以及“查看商品”“数据链接”“历史链接”。
- **缺失数据**：来源没有提供的指标显示为空或 `—`，不会用 0 虚构；来源真实为 0 的销量、销售额会保留为 0。

消息发送有重复保护。同一批采集结果、同一接收人、同一平台商品不会重复发送；任务表修改接收人或推送开关后，下一次发送会按最新任务表重新判断。

## 五、填写前检查清单

- [ ] 商品 ID 是商品 ID，不是完整链接、标题或店铺 ID。
- [ ] 商品 ID 与平台相匹配，TikTok 的长数字没有被表格改成科学计数法。
- [ ] 平台使用 `mercado`、`shopee` 或 `tiktok`。
- [ ] 需要采集时，监控开关为“开启”。
- [ ] 需要发送消息时，推送开关为“开启”。
- [ ] 数据推送人已选择飞书人员；负责人不等于数据推送人。
- [ ] 结果多维表链接和历史二维表链接指向正确的平台。
